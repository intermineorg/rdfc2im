# humanmine-items

The stock InterMine items-XML loader registered under its own type name, so that the integration
keys and model additions rdfc2im generates can travel with it. **No Java.**

```
humanmine-items.properties          have.large.file.xml.tgt = true
build.gradle                        verbatim from bio/sources/intermine-items-large-xml-file
resources/humanmine-items_keys.properties    generated by `rdfc2im project`, copied by `make fork-sync`
resources/humanmine-items_additions.xml      generated by `rdfc2im project`, copied by `make fork-sync`
```

## Why `resources/`, not `src/main/resources/`

`build.gradle` declares `resources { srcDirs = ['resources'] }`. That is the layout every Java-less
bio-source uses (`uberon`, `intermine-items-xml-file`); only sources with a converter use the
standard `src/main/resources/`. Files put in `src/main/resources/` here are **not** packaged, and
the load then dies in `DataLoaderHelper.getKeyProperties` with *"can't find keys for source"*.

`DataLoaderHelper` looks for `<sourceName>_keys.properties` first and falls back to
`<sourceType>_keys.properties`, so one `humanmine-items_keys.properties` serves every
`humanmine-*` source. The dbmodel plugin finds the additions the same way: it derives the filename
from the gradle project name (`humanmine-items` -> `humanmine-items_additions.xml`).

That also means **the keys are type-wide**: all `humanmine-*` sources share one key set. To key one
source differently, add a `humanmine-<source>_keys.properties` alongside these - the per-name file
wins.

## Why the *large* loader

`have.large.file.xml.tgt` retrieves through `FullXmlConverterTask`, which parses the items file with
SAX and stores each `<item>` as it reads it, then loads the tgt-items database into production.

The plain `have.file.xml.tgt` writes straight to production and skips the items database, which
looks like a saving - but `XmlDataLoader.processXml` calls `XmlBinding.unmarshal()` and holds the
whole file in memory as a `List<FastPathObject>` before storing anything. Fine for GO, fatal for a
full UniProt or ncbi-gene extract. Switch the properties line back only for small one-off files.

## Install

1. `make fork-sync` in the rdfc2im workspace (fills `resources/`).
2. Copy this directory into `humanmine-bio-sources/`, add `include 'humanmine-items'` to
   `settings.gradle`, then `./gradlew :humanmine-items:install`.
3. Use `out/_mine/project.xml`, and put each `out/<source>/items/<source>.xml` where its
   `src.data.file` points (`src_data_dir` in `rdfc2im.yaml`).
4. Merge `out/_mine/genomic_priorities.properties` into the mine's own - it lists only the
   `humanmine-*` writers, and every legacy source that still writes the same field must be added
   or the build will reject the ambiguity.
