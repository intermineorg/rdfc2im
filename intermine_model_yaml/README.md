# InterMine-labelled rdf-config models

Generated by `tools/gen_intermine_model_yaml.py`. One directory per rdf-config source (`go/`,
`ncbigene/`, `hgnc/`, ...), each containing `intermine_model.yaml`.

## What this is

Each file has exactly the same list/predicate/cardinality structure as that source's own
`in/config/<source>/model.yaml` (rdf-config's own description of what an RDF resource looks
like), but every local variable name is relabelled to the InterMine `Class.field` it maps onto,
read from that source's `out/<source>/mapping_predicates.sssom.tsv` and `mapping_subjects.tsv`.

So where rdf-config's own `model.yaml` says (for `go`):

```yaml
- Class obo:GO_0044255:
  - oboinowl:id+:
    - id: "GO:0044255"
```

this says:

```yaml
- Class[GOTerm] obo:GO_0044255:
  - oboinowl:id+:
    - GOTerm.identifier: GO:0044255  # rdf-config: id (sure)
```

Nested blank nodes are resolved and labelled the same way, walking down the same `Class/pred/pred/...`
path convention rdfc2im's own SSSOM files use for them (e.g. `Clinvar/classified_record/rcv_list`) -
not the arbitrary `_bn1`, `_bn2`... names a generic YAML parse would invent.

## Reading the labels

- `Class.field` in the variable's position: a real, loaded mapping. The trailing comment names the
  original rdf-config variable and its curation status (`sure`/`guess`/`human`), plus a `-> via
  Class.field` note when the value is attached through a reference/collection rather than directly.
- The original rdf-config variable name, kept as-is, with `# UNMAPPED (<status>) - <reason>`: a
  `todo`/`drop`/`link` row, or the source's converter simply never reads that RDF predicate.
  Nothing is silently dropped or guessed at - every unmapped row says why.
- A subject header's `[ClassName]` tag: which InterMine class that subject (or blank node)
  ultimately becomes. `[blank node]` means rdfc2im has no mapping-subjects row for it at all
  (rare - normally even flattened blank nodes get one, inheriting the parent's class).

## Known limitations

- **Quoting is a heuristic**, not preserved from the original file. rdf-config's own YAML parser
  (`rdfc2im.rdfconfig.parse_model`, reused here) discards the literal/CURIE distinction once
  PyYAML parses the file, so an identifier-shaped literal (e.g. `GO:0044255`) may show unquoted
  here even though the source file quotes it. This is cosmetic only - it does not affect which
  label is shown or what it means.
- **`homologene` and `expressionatlas`** have very few real mappings (matching `STATUS.md`'s own
  notes - both are still largely unmapped, pending spec decisions D7/D10).
- This is a read-only, point-in-time snapshot. Re-run `python3 tools/gen_intermine_model_yaml.py`
  after any `make translate` to refresh it - it is not wired into `make all`/`check`.
